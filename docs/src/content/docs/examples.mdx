Each example is a complete, commented `obsei.yaml` in the
[`examples/`](https://github.com/obsei/obsei/tree/master/examples) folder. The header of each file
lists the extras to install, the environment variables it reads and how to run it. Every example
is loaded with the real config loader in CI, so the keys match the current release.

```bash
git clone https://github.com/obsei/obsei && cd obsei
export OBSEI_DB_KEY="$(openssl rand -hex 24)" OBSEI_PSEUDONYM_SALT="$(openssl rand -hex 24)"
obsei try -c examples/social-listening.yaml        # preview redacted records; nothing stored or sent
obsei run -c examples/social-listening.yaml
```

Copy a file to `obsei.yaml` in your project and replace the placeholder ids, hosts and names.
Secrets are always read from environment variables.

## App reviews in six countries

App Store reviews from the US, UK, India, Brazil, Japan and Germany plus Google Play, classified
by a local Ollama model, with negative reviews posted to Slack and multilingual themes.

**Sources** `appstore`, `playstore` → **sinks** `slack` · extras `google,embeddings`

## Support tickets with a model cascade

Zendesk, Freshdesk and Intercom (EU region) tickets labelled by a small model; low-confidence
results go to a larger in-house model. Bugs become Jira issues, feature requests Linear issues,
and everything is exported to Parquet.

**Sources** `zendesk`, `freshdesk`, `intercom` → **sinks** `jira`, `linear`, `parquet`

## Enterprise, air-gapped

vLLM with an Azure OpenAI fallback behind a private egress allowlist, person-name redaction from a
local model, regional redaction, local multilingual embeddings, `k_anonymity: 10`, `obsei serve`
behind an SSO proxy with group-to-role mapping, API tokens, `allowed_hosts` and a retention job.

**Sources** `github_issues` (Enterprise), `webhook`, `sql` → **sinks** `jira`
· extras `mcp,names,embeddings,sql`
